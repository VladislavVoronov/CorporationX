# CorporationX — стартовый учебный проект

Независимый проект для VladislavVoronov и RedLothar на основе подготовленных заготовок [CorporationX](https://github.com/CorporationX). Здесь сохранены модели, репозитории доступа к БД, миграции, клиенты и настройки. Реализации учебных задач предстоит написать самостоятельно.

Все сервисы — обычные папки **одного репозитория**. Клонирование и push выполняются для этого репозитория целиком; git submodule не используется.

## Быстрый старт

Нужны JDK 17, Docker с Docker Compose и Python 3 для проверки запуска. Gradle скачивается через wrapper.

```bash
git clone https://github.com/VladislavVoronov/CorporationX.git
cd CorporationX
./infra/run.sh
./scripts/check.sh
cd user_service
./gradlew bootRun
```

Сначала запускайте `user_service`, затем `project_service`, затем остальные сервисы: исходные миграции проекта ссылаются на таблицу пользователей в общей БД.

Подготовленные API пользователя ещё не реализованы: работающий сервер может отвечать 404 на бизнес-запросы.

## Сервисы

| Папка | HTTP-порт | Назначение |
|---|---:|---|
| user_service | 8080 | Пользователи, цели, события, навыки |
| post_service | 8081 | Публикации, комментарии, реакции |
| project_service | 8082 | Проекты, команды, задачи |
| notification_service | 8083 | Заготовки уведомлений |
| achievement_service | 8085 | Достижения |
| analytics_service | 8086 | События аналитики |
| url_shortener_service | 8087 | Заготовка сокращателя ссылок |
| account_service | 8090 | Заготовка счетов |
| payment_service | 9080 | Подготовленная имитация оплаты |

Платёжный сервис из исходного каркаса возвращает успешную имитацию оплаты. Это вспомогательный компонент курса, а не решение задания. Модели счетов и сокращателя ссылок в исходных заготовках не подготовлены: их создание остаётся частью учебной работы.

## Проверки

```bash
./scripts/check.sh
python3 scripts/smoke.py
```

Первая команда последовательно выполняет проверки и собирает JAR всех девяти сервисов. Docker должен быть запущен для исходных контейнерных тестов. Вторая команда после запуска инфраструктуры проверяет старт каждого собранного приложения и HTTP-ответ, затем останавливает приложение. Реализации бизнес-сценариев этими проверками не подменяются.

В каждом сервисе можно отдельно выполнить `./gradlew check bootJar`.

## Пробы S3

После `./infra/run.sh` откройте консоль **http://localhost:19001**. Логин: `user`, пароль: `password`. Можно создавать корзины и загружать файлы вручную.

Для подключения SDK: endpoint **http://localhost:19000**, access key `user`, secret key `password`, region `us-east-1`, path-style addressing. Это локальные учебные реквизиты. Хранилище сохраняет файлы в Docker volume после остановки контейнеров.

Проверка совместимости с официальным AWS SDK:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/s3-smoke.py
```

Проверка создаёт временную корзину, загружает и читает файл, проверяет список объектов и подписанную ссылку, затем удаляет только созданные ею данные. Бизнес-реализация загрузок в сервисах остаётся учебной задачей.

Исходные фильтры сервисов требуют HTTP-заголовок `x-user-id`; для ручных проб передавайте, например, `x-user-id: 1`.

## Работа вдвоём

Создавайте ветку от `main` для каждой задачи, например `feature/user-registration`, затем pull request в `main`. Просматривайте изменения друг друга перед слиянием. Чтобы отправить изменения любого сервиса, делайте обычный commit и push из корня проекта.

## Источники и границы каркаса

Точные исходные коммиты каждого сервиса записаны в [STARTER-SOURCES.json](STARTER-SOURCES.json). Для `user_service` выбрана версия перед добавлением готового CRUD пользователя; для остальных сервисов — заготовки ветки `dev`, для инфраструктуры — `master`. Старые реализации комментариев и аналитики удалены из рабочей версии, но сохранены в истории этого репозитория.

Настройки окружения адаптированы для локального запуска: общая база курса, свободные порты инфраструктуры, локальная почта Maildev. Внешние SMS-реквизиты оставлены пустыми. Список людей из исходного CSV не переносится; пустой файл и JSON-схема сохранены для упражнений с импортом.

Все изменения инфраструктуры, сборки и исправления исходных заготовок перечисляются в [STARTER-NOTES.md](STARTER-NOTES.md). Проект не заявляет новую лицензию на исходный код CorporationX.
